================================================================================
        从0到1重新实现「金融AI研究助手」项目 — 完整开发步骤
================================================================================
关键依赖链：path_tool → config_handler → factory → vector_store → rag_service → agent_tools → react_agent → app.py



项目概述：
  基于 Streamlit 的金融研究分析平台，集成 ReAct Agent（LangGraph）、RAG 管道
  （ChromaDB + BM25 混合检索）、动态模型路由、定时报告推送、RAGAS 评估框架。

  目标领域：A股二级市场研报分析

步骤 2.2：编写 model/router.py（模型路由器）
--------------------------------------------------------------------------------
  依赖：langchain_core (BaseChatModel, AIMessage 等), model.factory (MODEL_CONFIGS)

  类的设计说明：
    核心思路：创建一个继承 langchain_core.BaseChatModel 的自定义类，对上层
    （Agent / RAG 服务）表现为一个普通的聊天模型，但内部根据用户输入的关键词
    动态选择底层实际调用的 LLM。

  类列表：

    1. LLMConfig @dataclass
       属性：
         provider: str           # 提供商标识（"openai"）
         model_name: str         # 模型名称（"qwen-plus" / "qwen-max"）
         temperature: float      # 生成温度
         api_key: str            # API密钥
         base_url: str           # API端点URL
         description: str        # 描述信息

    2. 函数 _detect_keywords(text: str) -> bool
       功能：检测文本中是否包含特定关键词
       实现：遍历关键词列表，判断是否在 text 中出现

    3. 类 ModelRouter
       职责：根据查询文本，决定使用哪个底层模型配置

       方法：
         __init__(self, configs: dict[str, LLMConfig])
           功能：初始化路由器，接收模型配置字典

         route(self, messages: list) -> LLMConfig
           功能：分析消息内容，返回应使用的模型配置
           实现规则：
             - 提取所有 HumanMessage 的内容合并为文本
             - 如果文本包含 "报告"/"研报"/"深度" -> 返回 "powerful" 配置
             - 如果文本包含 "分析"/"投资"/"估值"/"行业"/"产业链"/
               "行情"/"走势"/"财务"/"营收"/"利润"/"现金流"/"估值"/
               "基本面"/"技术面"/"政策"/"宏观" -> 返回 "standard" 配置
             - 默认返回 "fast" 配置

    4. 类 RoutableChatModel(BaseChatModel)  ⭐ 核心类
       职责：一个可路由的 LangChain 聊天模型，对上层透明

       属性：
         _router: ModelRouter          # 路由器实例
         _model_cache: dict            # 已创建的底层模型缓存（按配置缓存）

       方法：
         _route(self, messages: list) -> BaseChatModel
           功能：根据 messages 内容选择并返回实际的 LLM 实例
           实现：
             - 调用 self._router.route(messages) 获取配置
             - 生成缓存 key = f"{config.provider}_{config.model_name}"
             - 如果缓存中存在且温度一致则复用，否则创建新的 ChatOpenAI 实例
             - 创建时传入 model, temperature, api_key, base_url 参数
             - 检查是否有已绑定的 tools（self.tools），有则 .bind_tools()

         _generate(self, messages, stop, run_manager, **kwargs) -> ChatResult
           功能：同步生成（LangChain 框架要求实现）
           实现：self._route(messages).invoke(messages) -> 包装为 ChatResult

         _stream(self, messages, stop, run_manager, **kwargs) -> Iterator
           功能：流式生成（LangChain 框架要求实现）
           实现：self._route(messages).stream(messages)

         bind_tools(self, tools, **kwargs) -> "RoutableChatModel"
           功能：绑定工具列表（LangGraph Agent 会在调用时 bind_tools）
           实现：保存 tools 到 self.tools，返回 self（支持链式调用）

         _llm_type(self) -> str
           功能：返回模型类型标识字符串（"routable_chat_model"）

       关键注意事项：
         - ai_model_id 务必覆盖为 "routable_chat_model"（如果 LangChain 1.x 要求）
         - 必须正确实现 _generate 和 _stream，LangGraph Agent 会调用这两个方法
         - bind_tools 是 LangGraph 调用工具的关键，需要保存并在 _route 时应用

  验证步骤：
    python -c "
    from model.factory import chat_model
    from langchain_core.messages import HumanMessage

    # 测试普通问答（应路由到 fast 模型）
    msg = [HumanMessage(content='你好，介绍一下你自己')]
    for chunk in chat_model._stream(msg):
        print(chunk, end='', flush=True)
    print() "

步骤 3.1：编写 rag/vector_store.py（向量存储 + 混合检索）
--------------------------------------------------------------------------------
  依赖：langchain_chroma, langchain_text_splitters, rank_bm25, numpy,
        model.factory (get_embed_model), config_handler (chroma_conf),
        path_tool, file_handler, logger_handler

  类和函数列表：

    1. 类 BM25Retriever
       职责：基于 BM25 算法的关键词检索器
       属性：
         _index: BM25Okapi     # rank_bm25 索引实例
         _docs: list[str]      # 文档内容列表（用于返回结果）
         _metadatas: list      # 文档元数据列表

       方法：
         __init__(self, docs: list[str], metadatas: list[dict])
           功能：用文档列表构建 BM25 索引
           实现：
             - tokenize = lambda text: text.lower().split()  # 简单空格分词
             - self._index = BM25Okapi([tokenize(d) for d in docs])
             - 保存 docs 和 metadatas 用于结果返回

         search(self, query: str, k: int = 5) -> list[tuple[float, str, dict]]
           功能：BM25 关键词检索
           返回：[(score, doc_content, metadata), ...]  按分数降序排列

    2. 函数 rrf_fusion(vector_results, bm25_results, k=60, top_n=3)
       功能：Reciprocal Rank Fusion（倒数排位融合）算法
       参数：
         vector_results: [(score, doc, meta), ...]   # 向量检索结果
         bm25_results:  [(score, doc, meta), ...]   # BM25检索结果
         k=60: 平滑参数（默认值）
         top_n=3: 最终返回数量
       实现：
         - 为每篇文档分配来自两个检索源的排位（rank）
         - RRF score = Σ 1/(k + rank + 1)  对每种检索源的排位求和
         - 按 RRF score 降序排列，返回 top_n 篇去重文档

    3. 类 VectorStoreService  ⭐ 核心类
       职责：管理 ChromaDB 向量库 + BM25 索引的完整服务

       属性：
         _embed_model: DashScopeEmbeddings  # 嵌入模型
         _collection: Chroma.Collection     # ChromaDB 集合（懒加载）
         _bm25_retriever: BM25Retriever    # BM25 检索器
         _text_splitter: RecursiveCharacterTextSplitter  # 文档分块器

       方法：
         __init__(self)
           功能：初始化服务
           实现：
             - 获取嵌入模型
             - 创建文本分块器（chunk_size=200, overlap=20）
             - 调用 _init_collection() 懒初始化 ChromaDB
             - 调用 _init_bm25() 初始化 BM25 索引

         _init_collection(self) -> None
           功能：初始化 ChromaDB 集合（获取或创建）
           实现：
             - persist_directory = get_abs_path(chroma_conf["persist_directory"])
             - Chroma(collection_name, embedding_function, persist_directory)
             - 集合不存在时自动创建

         _init_bm25(self) -> None
           功能：从 ChromaDB 构建 BM25 索引
           实现：
             - 从 ChromaDB 获取所有文档内容和元数据
             - 创建 BM25Retriever 实例

         hybrid_search(self, query: str, k: int = 3) -> list[Document]
           功能：混合检索（向量 + BM25 -> RRF 融合）
           实现：
             - 向量检索：self._collection.similarity_search(query, k=2k)  # 取2倍候选
             - BM25检索：self._bm25_retriever.search(query, k=2k)
             - rrf_fusion() 融合两个结果集
             - 去重、返回 top-k 个 LangChain Document 对象

         get_collection_stats(self) -> dict
           功能：获取知识库统计信息
           返回：{"count": 分块数, "name": 集合名, "chunk_size": 分块大小}

         load_document(self) -> int
           功能：从 data/ 目录加载新文档到知识库（核心功能）
           实现流程：
             1. 从 data_path 下列出 .txt/.pdf 文件
             2. 读取 md5.txt（已加载文件的 MD5 记录）
             3. 逐个文件：
                a. 计算 MD5，如果已存在则跳过
                b. 根据后缀选用 pdf_loader 或 txt_loader 加载
                c. 为每个 Document 注入 "source" metadata（文件名）
                d. 用 text_splitter 分块
                e. 添加到 ChromaDB 集合
                f. 将 MD5 追加写入 md5.txt
             4. 重建 BM25 索引
             5. 返回新加载的文档数

  验证步骤：
    # 1. 初始化向量存储
    python -c "
    from rag.vector_store import VectorStoreService
    vs = VectorStoreService()
    print(vs.get_collection_stats())
    "

    # 2. 加载文档
    python -c "
    from rag.vector_store import VectorStoreService
    vs = VectorStoreService()
    count = vs.load_document()
    print(f'新增 {count} 个文档')
    print(vs.get_collection_stats())
    "
    确认：在 data/ 目录下放几个测试 PDF 文件，执行后 chroma_db/ 目录被创建

    # 3. 测试混合检索

步骤 3.3：编写 rag/reranker.py（文档重排序器）
--------------------------------------------------------------------------------
  依赖：无（纯算法实现）

  类列表：

    1. 类 LLMReranker
       职责：对检索结果进行去重和重排序

       方法：
         _deduplicate(self, docs: list[Document]) -> list[Document]
           功能：基于 Jaccard 相似度去重
           实现：
             - 截取每篇文档的前200个字符
             - 计算文档间的 Jaccard 相似度（字符级 2-gram）
             - 相似度 > 0.7 的视为重复，保留先出现的

         rerank(self, query: str, docs: list[Document], top_k: int = 3) -> list[Document]
           功能：对文档进行启发式评分重排序
           实现：
             - 先调用 _deduplicate()
             - 提取查询中的关键词（长度 >= 2 的中文词）
             - 逐文档打分：
               a. 标题/关键词匹配：元数据 source 或首行包含查询词 -> +2
               b. 关键词出现频率：每个关键词在文档中出现一次 -> +0.5
               c. 文档长度评分：100-500 字符 -> +1, <20 字符 -> -1
               d. 阈值过滤：min_score = 0.3，低于此分则丢弃
               e. 兜底保证：至少返回 1 个结果
             - 按评分降序返回 top_k 个

  模块级单例：
    reranker = LLMReranker()

  验证步骤：
    python -c "
    from rag.reranker import reranker
    from langchain_core.documents import Document

    docs = [
        Document(page_content='紫金矿业是一家以黄金和铜为主的大型矿业公司...', metadata={'source': '紫金矿业.pdf'}),
        Document(page_content='今天的天气很好适合出门游玩...', metadata={'source': '天气.txt'}),
        Document(page_content='紫金矿业2024年营收突破3000亿元...', metadata={'source': '紫金矿业年报.pdf'}),
    ]

    results = reranker.rerank('紫金矿业营收情况', docs)
    for i, doc in enumerate(results):
        print(f'排名{i+1} (来源:{doc.metadata[\"source\"]}): {doc.page_content[:80]}')
    "
    确认期望输出：
      - 紫金矿业年报 排名第1（与查询高度相关）
      - 紫金矿业介绍 排名第2（相关但不够精确）
      - 天气文档 被过滤掉

    边界情况分析：
      1. 所有文档都不相关时：至少返回 1 个（兜底策略）
      2. 完全重复的文档：Jaccard dedup 会去除
      3. 空查询词：所有文档得分为0 + 长度评分
      4. 超短文档（<20字符）：-1 惩罚

  常见问题：
    问题：Jaccard 相似度在中文场景的准确性
      -> 中文没有空格分词，2-gram 字符级比较可能不够准确
      -> 优化方案：使用 jieba 分词后再计算 Jaccard
      -> 当前实现简单直接，后续可优化

步骤 3.4：编写 rag/context_assembler.py（上下文组装器）

  类列表：

    1. 类 ContextAssembler
       职责：将检索到的文档按来源分组，在 token 预算内组装为 LLM 上下文

       方法：
         _group_by_source(self, docs: list[Document]) -> dict[str, list[str]]
           功能：按文档 metadata["source"] 字段分组
           返回：{"文件名1": ["分块1", "分块2"], "文件名2": ["分块3"]}

         _sort_groups(self, groups: dict, query: str) -> list[tuple[str, list[str]]]

             - 预算计算：1 token ≈ 2 个中文字符（粗略估计）
             - max_tokens * 2 = 字符预算上限
             - 超出预算时打印截断标记 "..."
             - 输出格式：
               --- 文档1：来源文件名 ---
               内容...
               --- 文档2：来源文件名 ---
               内容...

步骤 3.5：编写 rag/rag_service.py（RAG 编排服务） ⭐ RAG 核心
--------------------------------------------------------------------------------
  依赖：rag.vector_store, rag.query_rewriter, rag.reranker, rag.context_assembler,
        model.factory (chat_model), prompt_loader (load_rag_prompts),
        config_handler (chroma_conf), logger_handler

  类列表：

    1. 类 RagSummarizeService  ⭐ 核心编排类
       职责：协调整个 RAG 管道（改写 -> 检索 -> 去重重排 -> 过滤 -> 组装 -> 生成）

       属性：
         _vs: VectorStoreService    # 向量存储服务
         _rewriter: QueryRewriter   # 查询改写器
         _reranker: LLMReranker     # 重排序器
         _assembler: ContextAssembler  # 上下文组装器
         _model: BaseChatModel      # 回答生成模型
         _prompt: str               # RAG 回答 Prompt 模板

       方法：
         __init__(self)
           功能：初始化所有子组件
           实现：
             - self._vs = VectorStoreService()
             - self._rewriter = query_rewriter
             - self._reranker = reranker
             - self._assembler = context_assembler
             - self._model = chat_model
             - self._prompt = load_rag_prompts()

         _retrieve(self, query: str, k: int = 5) -> list[Document]
           功能：单次检索（hybrid_search + rerank）
           实现：
             - vs.hybrid_search(query, k=k) -> 候选
             - reranker.rerank(query, candidates, top_k=3) -> 最终3篇
           返回：重排序后的 top-3 文档

         retrieve_docs(self, query: str) -> list[Document]
           功能：多查询融合检索
           实现：
             - rewriter.rewrite(query) -> [子查询1, 子查询2, ...]
             - 并行（或串行）对每个子查询调用 _retrieve()
             - 按内容前100字符去重
             - 返回合并去重后的文档列表

         _filter_irrelevant_docs(self, query: str, docs: list[Document]) -> list[Document]
           功能：逐文档 n-gram 相关性过滤
           实现：
             - 从 query 提取 3-4 字符的 n-gram
             - 对每篇文档检查是否至少有一个 n-gram 出现在文档内容中
             - 丢弃不包含任何匹配 n-gram 的文档

         _check_context_relevance(self, query: str, docs: list[Document]) -> bool
           功能：全局上下文相关性检查
           实现：
             - 合并所有文档内容
             - 检查至少一个 3-4 字符 n-gram 匹配
             - 额外检查股票代码（6位数字）是否存在
             - 返回 True/False

         summarize(self, query: str) -> str
           功能：完整 RAG 管道，生成最终回答 ⭐ 主方法
           实现流程：
             1. retrieve_docs(query)             # 多查询检索
             2. _filter_irrelevant_docs(query)    # 逐文档过滤
             3. 如果无文档：返回 "未找到相关信息"
             4. _check_context_relevance(query)   # 全局相关性检查
             5. 如果相关性检查失败：返回 "检索结果与问题不相关"
             6. context = _assembler.assemble(query, docs)  # 组装上下文
             7. prompt = self._prompt.format(context=context, question=query)
             8. result = self._model.invoke(prompt)          # LLM 生成
             9. 返回 result.content

         summarize_with_context(self, query: str) -> dict
           功能：同 summarize()，但额外返回检索到的上下文（用于评估）
           返回：{"answer": str, "contexts": list[str]}

  验证步骤：

    python -c "

    # 测试2：带上下文的调用（用于后续评估）
    result = rag.summarize_with_context('紫金矿业的黄金产量')
    print('=== 回答 ===')
    print(result['answer'])
    print('=== 上下文文档数 ===')
    print(len(result['contexts']))
    "

    确认：
      - 有相关知识库时，返回有引用来源的回答
      - 无相关知识库时，返回 "未找到相关信息"
      - summarize_with_context 返回正确的字典结构
      - 日志中能看到检索 -> 过滤 -> 组装 -> 生成的完整流程

  测试场景规划：
    场景1：知识库内的问题
      -> 预期：返回基于文档的回答，有来源引用
    场景2：知识库外的问题（如 "今天天气怎么样"）
      -> 预期：返回 "未找到相关信息" 或相关性警告
    场景3：超长问题（> 500 字）
      -> 预期：正常处理，n-gram 过滤正常工作
    场景4：无知识库时
      -> 预期：返回明确的无相关文档提示

    处理指标：

       功能：LLM 调用前记录状态

         - 记录最后一条消息的类型和内容前100字符

    5. 函数 report_prompt_switch(state, runtime)  — dynamic_prompt 钩子
       功能：当上一步调用了 generate_report 工具时，切换为研报生成 Prompt
       实现：
         - 检查最近一次工具调用是否为 generate_report
         - 是 -> 返回 load_report_prompts() 的内容作为系统提示词
         - 否 -> 不干预（保留原有 Prompt）

    6. 函数 response_quality_guard(state, runtime)  — after_model 钩子
       功能：LLM 输出后质量检查
       实现：
         - 检测空输出 -> logger.warning()
         - 检测可疑金融术语（"暴涨"、"保证收益"、"稳赚"等）-> logger.warning()
         - 检测输出过短（< 20 字符且问题长度 > 20）-> logger.warning()

    7. 函数 build_middleware() -> list
       功能：构建并返回全部中间件列表
       返回：按正确顺序排列的中间件列表

步骤 5.1：编写 agent/react_agent.py（ReAct Agent 核心）⭐ Agent 核心
--------------------------------------------------------------------------------
  依赖：langgraph, langgraph-checkpoint-sqlite, langchain_core,
        model.factory (chat_model), prompt_loader (load_system_prompts),
        agent.tools (所有工具), agent.tools.middleware (build_middleware),
        path_tool, logger_handler

  类列表：

    1. 类 ReactAgent
       职责：基于 LangGraph 的 ReAct Agent，管理对话、持久化和流式执行

       属性：
         _model: RoutableChatModel   # 可路由的聊天模型
         _system_prompt: str         # 系统提示词
         _tools: list                # 可用工具列表
         _agent: CompiledGraph       # 编译后的 LangGraph agent
         _db_path: str               # SQLite 数据库路径

       方法：
         __init__(self)
           功能：初始化 Agent 及所有依赖
           实现：
             - self._model = chat_model
             - self._system_prompt = load_system_prompts()
             - self._tools = [所有 agent_tools + news_tools + search_tools + stock_tools]
             - self._db_path = get_abs_path("data/conversations.db")
             - 确保 data/ 目录存在
             - 构建 LangGraph agent：
               a. create_react_agent(
                    model=self._model,
                    tools=self._tools,
                    system_prompt=self._system_prompt,
                    middleware=build_middleware()
                  )
               b. 使用 InMemorySaver() 作为检查点（或 SqliteSaver）
             - 初始化数据库表（threads 表）

         _ensure_db(self) -> None
           功能：确保 SQLite 数据库和表存在
           实现：
             - 使用 sqlite3 连接 data/conversations.db
             - 创建 threads 表（如果不存在）：
               CREATE TABLE IF NOT EXISTS threads (
                 thread_id TEXT PRIMARY KEY,
                 title TEXT DEFAULT '新对话',
                 created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
                 updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
               )
             - 启用 WAL 模式（PRAGMA journal_mode=WAL）
             - 设置 busy_timeout=5000

         create_thread(self) -> str
           功能：创建新对话线程
           实现：生成 UUID 作为 thread_id，插入 threads 表，返回 thread_id

         list_threads(self) -> list[dict]
           功能：列出所有对话线程（按更新时间降序）
           返回：[{thread_id, title, created_at, updated_at}, ...]

         delete_all_threads(self) -> None
           功能：删除所有对话线程
           实现：DROP TABLE threads 后重建

         update_thread_title(self, thread_id: str, title: str) -> None
           功能：更新对话标题
           实现：UPDATE threads SET title=?, updated_at=CURRENT_TIMESTAMP

         auto_title(self, thread_id: str, first_message: str) -> None
           功能：根据首条用户消息自动生成标题
           实现：截取前 20 个字符 + "..."

         touch_thread(self, thread_id: str) -> None
           功能：更新对话的最后活跃时间
           实现：UPDATE threads SET updated_at=CURRENT_TIMESTAMP

         load_messages(self, thread_id: str) -> list
           功能：加载指定对话线程的历史消息
           实现：
             - 从 LangGraph checkpoint 中获取状态
             - 从 state 提取 messages 并格式化
             - 返回消息列表供 Streamlit 渲染

         execute_stream(self, query: str, thread_id: str | None = None) -> Iterator
           功能：流式执行 Agent 对话 ⭐ 主方法
           参数：
             query: 用户输入
             thread_id: 对话线程ID（None 时自动创建）
           实现：
             - thread_id 为 None 时调用 create_thread()
             - 配置 config = {"configurable": {"thread_id": thread_id}}
             - 调用 self._agent.stream(
                 {"messages": [HumanMessage(content=query)]},
                 config=config,
                 stream_mode="messages"
               )
             - 遍历流式输出：
               a. 如果是 ToolMessage：yield {"type": "tool", "name": tool_name, "content": content}
               b. 如果是 AIMessage（含 content）：yield {"type": "token", "content": token}
               c. 如果是 AIMessage（含 tool_calls）：yield {"type": "tool_call", "name": ...}
             - 异常处理：
               a. 403/401 -> "API Key 无效或配额已用尽，请检查 DASHSCOPE_API_KEY"
               b. Timeout -> "请求超时，请稍后重试"
               c. 通用异常 -> 记录日志并返回友好错误消息
             - finally：更新 thread 的 updated_at 时间戳

步骤 7.1：编写 app.py（Streamlit 主应用）⭐ 最终入口
--------------------------------------------------------------------------------
  依赖：streamlit, agent.react_agent (ReactAgent), rag.vector_store,
        agent.scheduler (ReportScheduler), logger_handler

  文件和函数结构：

  1. 页面配置函数 configure_ui()
     功能：设置 Streamlit 页面配置和自定义 CSS 样式
     实现：
       - st.set_page_config(
           page_title="金融AI研究助手",
           page_icon="📈",
           layout="wide",
           initial_sidebar_state="expanded"
         )
       - st.markdown() 注入自定义 CSS：
         金融风格配色（深蓝主色调 + 金色强调色）
         卡片式聊天界面
         自定义侧边栏样式
         响应式设计

  2. 会话状态初始化函数 init_session_state()
     功能：初始化 Streamlit st.session_state 变量
     实现：
       - "agent": ReactAgent 实例（只初始化一次）
       - "vs": VectorStoreService 实例（只初始化一次）
       - "scheduler": ReportScheduler 实例（只初始化一次）
       - "messages": list[dict]  # 当前对话的消息列表
       - "thread_id": str        # 当前对话线程ID
       - "running": bool         # 是否正在执行
       - "stop": bool            # 停止信号

  3. 侧边栏渲染函数 render_sidebar()
     功能：渲染 Streamlit 侧边栏内容
     实现：
       a. 知识库状态区：
          - vs.get_collection_stats() 显示统计信息
          - "刷新知识库" 按钮 -> vs.load_document()
          - 显示已加载的文档列表
       b. 对话管理区：
          - "新建对话" 按钮 -> agent.create_thread()
          - "清空对话" 按钮 -> agent.delete_all_threads()
          - 对话历史列表（可选切换）
          - "导出对话" 按钮 -> 下载当前对话为 MD 文件
       c. 定时任务状态区：
          - 显示调度器运行状态
          - 手动触发任务按钮
       d. 示例查询区：
          - 4个预置示例（紫金矿业、有色金属、贵州茅台、阳光电源）

  4. 示例查询点击处理函数 on_example_click()
     功能：点击示例查询后将问题填入输入框并触发搜索

  5. 消息渲染函数 render_messages()
     功能：渲染对话消息列表
     实现：
       - 遍历 st.session_state["messages"]
       - 区分用户消息、助手消息、工具调用消息
       - 使用 st.chat_message() 渲染
       - 助手消息支持 Markdown + 引用块（来源标注）
       - 错误消息用红色样式突出显示

  6. 用户输入处理函数 handle_user_input()
     功能：处理用户输入，启动 Agent 执行
     实现：
       - 获取 st.chat_input() 内容
       - 添加用户消息到 messages
       - 调用 _start_run(query)

  7. Agent 执行函数 _start_run(query: str)
     功能：启动 Agent 后台执行，轮询流式结果
     实现：
       - 设置 running = True
       - 启动后台线程调用 agent.execute_stream()
       - 主线程轮询（time.sleep(0.5) + st.rerun()）
       - 每次轮询从队列中获取新 chunk
       - 根据 chunk type 更新 messages：
         type == "token" -> 追加到当前助手消息
         type == "tool"  -> 插入工具调用消息（折叠展示）
       - 完成后设置 running = False
       - 更新对话标题（自动生成）

  8. 停止处理函数 handle_stop()
     功能：停止按钮回调
     实现：设置 stop = True，终止后台执行

  9. 主函数 main()
     功能：组织整个 Streamlit 应用流程
     实现：
       configure_ui()
       init_session_state()
       render_sidebar()
       render_messages()
       handle_user_input()

  10. 入口：if __name__ == "__main__": main()

  ⚠️ 关键注意事项：
    - Streamlit 的 rerun 机制意味着每次交互都会重新执行脚本
      需要使用 st.session_state 保存需要持久化的状态
    - 后台线程中的 agent 执行需要线程安全的数据共享（队列）
    - 错误状态需要优雅处理（API 额度用尽、网络超时等）
    - 停止按钮需要真正能终止 Agent 执行（不能仅设置标志位）

  验证步骤：

      b. 新建对话：点击按钮后创建新线程
      c. 发送消息：输入问题后看到流式回答
